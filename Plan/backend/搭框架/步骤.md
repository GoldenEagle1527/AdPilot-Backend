# 后端搭框架：步骤

按顺序做。规范：[`../../../meta/公司研发规范.md`](../../../meta/公司研发规范.md)、[`../../../architecture/部署.md`](../../../architecture/部署.md)。

## 0. 仓库与机器

1. 在**后端应用仓**里做（与前端仓分开）。实现期对该仓 `git init`，分支 `feat/framework`。不要往当前这份 `Plan/` 工作区或前端仓塞 FastAPI。
2. **不要装宝塔**。不要本机再起 Postgres/Redis。连**本仓** `deployment/dev.yaml` 里的 192.168.112.12（键名对齐当前工作区示例）。
3. 进程监听 `0.0.0.0`，**打开本机防火墙**对应端口（yaml 里 `listen_port`，默认 8000），以便对方电脑上的前端能打进来。
4. `GET /api/v1/ready` 核对远端是 PostgreSQL 18.x、Redis 7.2.x。

## 1. 目录

按 [`../FastAPI目录.md`](../FastAPI目录.md) 建 `backend/`。另：

- 配置只读仓库根 `deployment/*.yaml`（PyYAML，MIT）。**不用 dotenv。**
- 应用 Dockerfile 以后放 `dockerfile/backend.Dockerfile`，不要把 redis/postgres 写进该镜像。

不要出现全站 `app/routers`、`app/models`、`app/permissions.py`。

## 2. 依赖

`pyproject.toml` + `backend/许可证.md`：

| 包 | 用途 | 许可证 |
| --- | --- | --- |
| fastapi | HTTP | MIT |
| uvicorn | 进程 | BSD-3 |
| pydantic | 校验 | MIT |
| sqlalchemy | ORM 2.x asyncio | MIT |
| alembic | 迁移 | MIT |
| asyncpg | PG 驱动 | Apache-2.0 |
| redis | Redis asyncio | MIT |
| pyyaml | 读 deployment yaml | MIT |

不要加 psycopg*。Python 3.12.x。

## 3. core

1. 从 `deployment/dev.yaml` 读库、Redis、CORS、监听地址。
2. CORS 允许源来自 yaml；对方发群前端 URL 后再补进 `cors_origins`。
3. 信封与分页按文档。
4. SQLAlchemy async engine / session；Redis 客户端。`core` 不定义 User/Role 表。
5. Alembic 能跑。本阶段随后可按契约迁 **登录/用户/权限/角色** 相关表，不要先做投放业务表。
6. Token 只从 **Authorization Header** 读。登录密码流程当前 **mock**。

## 4. 健康检查

`GET /api/v1/health`、`GET /api/v1/ready`。  
OpenAPI 可从局域网打开：`/openapi.json`、`/docs`。变更接口时按 [../接口变更对接.md](../接口变更对接.md) 发对接文本。

## 5. 挂载 `system_admin`

空挂前缀 `/api/v1/system-admin`。本阶段**定义**登录/用户/权限/角色（契约 + 模型）；不要实现投放 CRUD，不要先写完整部门管理除非契约已写。

## 6. 自检

进程能起；本机以外能访问（防火墙）；ready 能连上 192.168.112.12；许可证表填全；按 [验收.md](验收.md) 勾选。把本机局域网 IP 和端口告诉前端。
