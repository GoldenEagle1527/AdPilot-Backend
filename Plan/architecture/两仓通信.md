# 两仓怎么通信

状态：accepted  
ADR：[0018](../decisions/0018-前后端两个Git仓库.md)（两仓）、[0019](../decisions/0019-后端OpenAPI对接.md)（怎么对接）

只有 **后端仓** 和 **前端仓**。本目录 `Plan/` 是现在写计划用的，**不是**第三个仓库，前端不必 clone。

## 谁说了算

后端做主。需求在**线下或群**里定。前端不另维护契约、不实现自有业务逻辑。

| 传什么 | 走哪 | 谁写 |
| --- | --- | --- |
| 要做什么 | 群 / 线下 | 两边说 |
| 字段、类型、路径、错误码 | 后端 **OpenAPI**（前端自己拉） | 后端 |
| 接口刚变了 / 新加了 | 群里一段**对接文本** | 后端，每次变更必发 |
| 前端 origin、后端局域网地址 | 群 | 各改自己仓的 yaml |

## 后端改接口时

1. 改代码，保证 OpenAPI 是新的（FastAPI 自动出的即可）。
2. 按 [../backend/接口变更对接.md](../backend/接口变更对接.md) **写一段对接文本发群**。只写「变了什么 / 新了什么」，不贴整份 schema。
3. 前端按文本去拉 OpenAPI，改自己的请求。

没有对接文本 = 前端可以当没这回事。OpenAPI 拉不到 = 前端不要猜字段。

## 前端必须遵守

- 所有业务数据、校验规则、权限、列表过滤，只来自后端接口。
- 禁止在前端写一套「自己的」计算再当结果用（包括本地拼权限、本地算默认密码、本地过滤部门树当权限）。
- 页面只：发请求、拆信封、按返回值画界面。

## 运行时

| 谁改 | 改哪 | 消息从哪来 |
| --- | --- | --- |
| 前端把 origin 发群 | 后端仓 `cors_origins` | 群 |
| 后端把 API 基址发群 | 前端仓 `api_base` | 群 |

禁止子模块互挂两个应用仓。
