# 信封与分页

状态：accepted
本进程必须按此实现。改形状 = 破坏性，走契约版本规则并通知调用方。

实现只有一处：`app.core.envelope`（`success` / `ApiError` / 全局异常处理器）。业务代码不自己拼 dict。

## 成功

```json
{
  "code": 200,
  "message": "成功",
  "data": {}
}
```

`data` 可以是对象、数组或 `null`。成功只用 HTTP 200，不用 201 / 204。

## 失败

```json
{
  "code": 404,
  "message": "给人看的一句话",
  "data": null
}
```

`code` 是整数，恒等于 HTTP 状态：业务失败 400/409、未登录 401、没权限 403、不存在 404、校验失败 422、自身 bug 500、下游不可用 503。禁止 200 里包业务失败。

区分场景写在 `message`，不再有 `UNAUTHORIZED` 这类大写蛇形错误码。各契约的「错误」表只列情况和 HTTP 状态。

## 分页（列表的 `data`）

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "page_size": 20
}
```

查询参数：`page`（从 1 起）、`page_size`（默认 20，上限 100）。空结果是 `list: []` + `total: 0`，不把 `data` 设成 `null`。不分页的树仍是 `data: { "items": [] }`。

时间字段：ISO-8601 UTC 带 `Z`，实现用 `app.core.times.iso8601_z`。主键对外 string，库内 PostgreSQL 整数 Identity 自增。

## 健康检查（框架就做，不算业务契约）

- `GET /api/v1/health` → 进程活着，信封 + `data: { "status": "ok" }`
- `GET /api/v1/ready` → 能连上 PostgreSQL 18 与 Redis 7.2，否则 503

## 变更历史

- 2026-09-22：信封由 `{ ok, data, error }` 改为 `{ code, message, data }`，分页 `items` 改 `list`，取消大写蛇形错误码（对齐公司微服务规范）。破坏性，全部接口同时生效。
