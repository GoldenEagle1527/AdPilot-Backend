# 部署

状态：accepted  
ADR：[0017](../decisions/0017-Docker与共用库.md)

## 目录

当前工作区里的 `deployment/`、`dockerfile/` 是**键名示例**。真正的文件在各自应用仓根目录：

```
# 后端仓
deployment/dev.yaml      # listen、cors_origins、postgres、redis
dockerfile/backend.Dockerfile

# 前端仓
deployment/dev.yaml      # api_base（及前端自己的监听若需要）
dockerfile/frontend.Dockerfile
```

不要在 Dockerfile 里 `FROM redis` / `FROM postgres` 当本项目的库。两端不要共用同一份会互相覆盖的 yaml。

## 开发环境

后端进程跑在后端这台机器，监听 `0.0.0.0`，防火墙放行端口（默认 API `8000`，以**后端仓** yaml 为准）。  
前端在另一台机器，API 基址指向后端机器的局域网地址（写在**前端仓** yaml）。CORS 允许源等对方把前端 URL 发群后写入**后端仓** `cors_origins`。

**开发/测试**：本机 Docker Compose 起 Postgres 18、Redis 7.2 和 API，数据在本机卷里（ADR 0020）。不要连 192.168.112.12。  
**生产**：才连 192.168.112.12 共用实例。不要用宝塔。

配置从该应用仓的 yaml 读，不用 dotenv。跨仓怎么通知：[两仓通信.md](两仓通信.md)。
