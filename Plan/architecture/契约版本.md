# 契约：最新表与变更历史

状态：accepted  
对外真源是 **OpenAPI**（ADR 0019）。下面 markdown 只给本仓留底。接口变更仍必须发 [../backend/接口变更对接.md](../backend/接口变更对接.md)。

## 最新表、目录、历史：不要再抄一份字段表

| 文件 | 是什么 | 不是什么 |
| --- | --- | --- |
| `contracts/<endpoint>.md` 的请求/响应表 | **该接口的最新表** | 不要另做一份「最新参数.xlsx」 |
| 同一文件的「变更历史」 | 每次改了什么（日期、版本、是否破坏） | 不要把旧字段表整段贴在历史里（破坏性变更除外） |
| `contracts/最新表.md` | 本模块全部接口的最新目录（一行一个：版本、方法、路径、干什么） | 不要在这里再抄字段 |
| `contracts/_history/<endpoint>-vN.md` | **破坏性变更前**的全文快照 | 兼容变更不必做快照 |

## 版本

每个契约头上有：

- **文档版本**：整数，从 `1` 起，**每次**改请求/响应/错误/路径/语义都 +1。
- **路径版本**：`/api/v1/...`。只在破坏性变更时升到 `v2`（删字段、改语义、改路径）。

兼容变更（加可选字段、加错误码说明）：文档版本 +1，路径仍 `v1`，只写变更历史，不做快照。

## 改接口时 Agent 必做

1. 判断是否破坏性。若是：把**改之前**的契约全文复制为 `_history/<endpoint>-v<旧文档版本>.md`。
2. 改当前 `contracts/<endpoint>.md` 的最新表；文档版本 +1。
3. 在「变更历史」**最上行**追加：日期、新版本、是否破坏、改了哪几个字段/含义、作者。
4. 更新 `contracts/最新表.md` 对应行的版本与日期。
5. 实现代码与最新表不一致 = 未完成。
6. 对外：更新 OpenAPI，并发对接文本。见 [两仓通信.md](两仓通信.md)。

只改说明文字、不改语义：可以不升文档版本，但仍在历史里记一行「文档」。
