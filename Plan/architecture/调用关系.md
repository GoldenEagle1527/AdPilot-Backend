# 页面卡片与调用记录

状态：accepted  
范围：Agent 实现接口或写页面时，记「谁调用谁」。参数真源仍是契约。

## 要不要维护一张总表

要维护的是 **调用关系**，不是再抄一份参数手册。

| 问题 | 写在哪 | 不要写在哪 |
| --- | --- | --- |
| 哪个模块提供哪些接口、参数、干什么 | `modules/<id>/contracts/<endpoint>.md`（**当前即最新表**）；`contracts/最新表.md` 一行目录；`后端.md` 认领 | 页面文件里再贴一遍请求/响应表；另做「最新参数.xlsx」 |
| 接口改过什么 | 该契约底部「变更历史」；破坏性全文在 `contracts/_history/` | 只靠 git log；把旧字段表贴进历史（破坏性快照除外） |
| 哪个页面调用了哪个接口、页面动作是什么 | `modules/<id>/pages/<page>.md` | 全站一张巨表；`Plan/前端/` 这种跨业务目录 |
| 传参是什么 | **契约的请求表**。页面卡片只写「本动作用到契约里哪些字段名」，不写类型、必填、错误码 | 页面卡片复制整张字段表 |

两份字段表一定会漂。页面卡片漏了字段名可以补；和契约类型不一致时 **以契约为准**。

## 文件夹（按业务，不按「前端/」）

不要：`Plan/前端/系统管理页/明细.md`（会拆掉一业务一块，系统管理和以后的投放会混在同一棵「前端」树里）。

要：

```
Plan/modules/<business-id>/
  后端.md                 本模块提供哪些接口（认领）→ 链到 contracts/
  contracts/最新表.md        本模块接口最新目录（版本/路径/干什么）
  contracts/<endpoint>.md    最新字段表 + 变更历史
  contracts/_history/        破坏性变更前的全文快照
  pages/
    说明.md                  本模块有哪些页面
    <page>.md                这一页调了哪些契约
```

`system-admin` 示例：`Plan/modules/system-admin/pages/部门管理.md`  
对应日后代码：`frontend/src/modules/system-admin/pages/departments/`

壳（顶栏/侧栏）不是业务页：调用公开能力的记录放 `Plan/modules/system-admin/pages/壳.md`（壳消费 B 类接口）。

## Agent 何时改

| 动作 | 必须改 |
| --- | --- |
| 新增接口 | 契约（文档版本 1）；`最新表.md` 一行；`后端.md` 一行 |
| 改接口 | 当前契约最新表；文档版本 +1；变更历史上插一行；`最新表.md` 该行。破坏性：先快照 `_history/`。细则：[契约版本.md](契约版本.md) |
| 已有页面在用 | 同步那些 `pages/*.md` 的调用表与字段名；契约「被谁调用」 |
| 新增/改页面调用 | 该 `pages/<page>.md`；对应契约的「被谁调用」 |
| 只改样式、不改请求 | 不必改卡片 |

旧页面必须停在旧版时：卡片注明文档版本，链到 `_history/`，不要假装仍对着最新表。

实现代码与卡片、契约三者不一致 = 未完成。

## 页面卡片里「传参」怎么写

只列字段名，指向契约：

```
| 加载列表 | [list-departments.md](../contracts/list-departments.md) | query: name, status |
```

类型、必填、错误见契约。契约不存在则这行不算可实现。实际请求发往 **后端机**（基址可配），见 [前后端分机.md](前后端分机.md)。
