# 怎么分给不同的人

状态：accepted  
实例：[融合.md](融合.md)。

## 当前阶段（先于业务认领）

| 人 | 工作包 | 执行 |
| --- | --- | --- |
| 后端一人 | 整个后端框架 | [../backend/搭框架/说明.md](../backend/搭框架/说明.md) |
| 前端一人 | 整个前端框架（React 已定） | [../frontend/搭框架/说明.md](../frontend/搭框架/说明.md) |

不要把「搭框架」再拆成两人合写 core。业务接口仍按下面第 3 层认领。

## 默认顺序

先按**业务块**，再按端，再按**一个接口或一个页面**。  
`system-admin` 内部的部门/用户/角色是包内文件，不是三个业务。

## 工作包

| 工作包 | 谁先 | 产出 |
| --- | --- | --- |
| 单接口契约 | 领该接口的人 | `modules/<id>/contracts/<endpoint>.md` + `最新表.md` 一行 |
| 该接口实现 | 同一人（契约之后） | 该业务包内一个 router 文件 |
| 使用该接口的页面 | 领页面的人 | 只引用契约 |
| 新业务块 | 复制模板 | `modules/<id>/` 全套 |

没有契约字段表，不算实现可开工。清单可以先列（system-admin 已列），字段后写。改已有契约走 [契约版本.md](契约版本.md)，不要另起第二份字段表。

## system-admin 上的实例（契约未写）

同一块业务、可并行的认领面：

| 人 | 后端文件（日后） | 页面（日后） |
| --- | --- | --- |
| A | `departments.py` + 部门标签/改父 | 部门管理 |
| B | `roles.py` + `role_menus.py` | 角色管理（含分配菜单） |
| C | `users.py` + `user_roles.py` + `user_data_scope.py` + 重置密码 | 用户管理 |
| D | `menu_nodes.py` 查询 | 权限角色查询 |
| E | `session_queries.py`（公开能力 B） | 无独立页；壳和其它业务消费 |

A 与 B 需要角色目录时：B 的契约是真源，A 只调公开查询，不抄角色表结构。
