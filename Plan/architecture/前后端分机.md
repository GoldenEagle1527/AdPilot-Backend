# 前后端分机

状态：accepted  
ADR：[0012](../decisions/0012-前后端分两机部署.md)

前端和后端部署在 **两台独立机器** 上。切块仍按业务；这一条只锁运行与通信形态。

## 两套产物，两台机器

```
浏览器
  → 前端机（静态资源 / 前端进程）
      → HTTP（契约路径，基址可配）
          → 后端机（一个 FastAPI 进程，一业务一包）
```

| 端 | 机器上有什么 | 没有什么 |
| --- | --- | --- |
| 前端机 | 页面、壳、按业务切的前端模块 | 数据库、ORM、业务包内部实现 |
| 后端机 | FastAPI、业务包、库 | 业务页面、用后端去托管正式前端 |

开发时前端 dev server 代理到后端可以，那是本机方便，**不是**上线拓扑。

## 前端必须可配后端地址

前端 `shared` 只准放：API 基址怎么读、怎么发请求、错误信封怎么拆。  
基址来自配置，不写进某个业务页。路径以 OpenAPI 为准；完整 URL = 配置的基址 + 路径。  
前端禁止自有业务逻辑，业务请求必须打后端（ADR 0019）。

## 后端必须开 CORS

`core` 用 `deployment/*.yaml` 列出允许的前端源。不要 `*` 配带 Cookie 的方案。业务包不各自写 CORS。开发时等对方发群前端 URL 再写入 `cors_origins`。

## 登录态

Token 放 **Authorization Header**（ADR 0016）。密码登录，当前 mock。不要写 Cookie 域。

## 禁止

- 生产用 FastAPI `StaticFiles` / 模板渲染当正式前端
- 页面里写死 `http://192.168.x.x:8000`
- 前端 import 后端 Python 包；后端 import 前端组件
- 靠「同源相对路径 `/api/...`」当唯一配置
