# 模块化：一个业务一块

状态：accepted  
实例：[融合.md](融合.md)（system-admin）。本文件只留通则。

## 定义

一个**业务块**可单独加入、单独给人维护：

- 稳定 id（kebab-case）
- 一个后端包、一块前端目录、自己的 `contracts/`
- 两端代码可以同仓；**运行时**前端在前端机、后端在后端机（[前后端分机.md](前后端分机.md)）
- 领域数据住在本块；**不**自建角色管理台（见下）

当前已登记：`system-admin`。投放 / 素材 / 报表未开块。

## 权限放哪

| 东西 | 住哪 |
| --- | --- |
| 角色、菜单树、部门数据范围、系统管理页 | `system-admin` |
| 其它业务的页面入口 | 菜单树上的节点（数据仍属 system-admin） |
| 其它业务的领域表 | 各自的业务块 |
| 登录态 | shared |

## 目标代码落点（实现期，现在不建）

```
backend/app/
  core/                         # shared 白名单
  modules/
    system_admin/               # 第一块
    <next>/                     # 以后

frontend/src/
  shared/
  shells/                       # 槽位；菜单内容问 system-admin 公开能力
  modules/system-admin/
  modules/<next>/

Plan/modules/<business-id>/
```

## 允许的依赖

```
本块页面     --HTTP--> 本块契约（后端机）
未来业务包    --> system-admin 公开能力（有效菜单 / 可见部门 / require_menu）
业务包        --> core
业务包       -x-> 另一包的 ORM / 私有函数
前端         -x-> 后端 Python 包（禁止 import）
```

`system_admin` 不得反向依赖尚未存在的投放包。

## 新业务准入

复制 [`../modules/_template/`](../modules/_template/)。不要新开「权限」业务块。
