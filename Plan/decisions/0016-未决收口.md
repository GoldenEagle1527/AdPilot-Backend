# ADR 0016：未决问题收口（研发回复）

状态：accepted

来源：`回复.md`（2026-09-20）。机制原文仍见 [0010](0010-锁定机制不锁定清单.md)；**清单与行为细则以本 ADR 为准**。

## Git

- 产品名 **AdPilot**（不是 drooling）。远程仍预定 `http://git.73oc.local/`，现在只本地 `git init`，不加 origin、不 push。  
  **仓数**：[0018](0018-前后端两个Git仓库.md) 两个应用仓。`AdPilot` 留给后端。不建计划远程（[0019](0019-后端OpenAPI对接.md)）。
- 大文件放云盘，小文件进 git（Q-GIT-2）。
- 本地 init 已执行（Q-GIT-3）。

## 认证

- Token 放 **Authorization Header**（Q-AUTH-1）。不要 Cookie 方案。
- 登录协议：**密码登录**。当前用 **mock 数据**（Q-AUTH-2）。不做 SSO。

## 开发拓扑（Q-DEP-1）

开发环境：后端跑在后端负责人这台机器上（须监听并可从局域网访问，**开防火墙端口**）；前端跑在另一台机器上，前端 origin 由对方发群后再写入 CORS。不是生产主机名。

## CI

暂无 CI/CD，手动发布。

## 权限清单与行为

- **Q-PERM-6**：本阶段菜单/组件/角色清单 **按** `管理中台截图/5.4.0.权限管理-权限角色查询表.xlsx`（即 `权限清单-参考.md` 全文）。投放等**页面不预建**（Q-FE-2），但树上可以有这些节点名作为数据。
- **Q-PERM-2**：有效功能权限 = 用户角色菜单 ∪ 部门角色菜单。负责人/成员不改变该并集；以后要改算新需求。
- **Q-PERM-3**：勾父部门 = 选中其全部子孙，可再手动取消个别子孙。数据权限空集合 = 无对应数据权限（看不见按部门隔离的业务数据）。
- **Q-PERM-4**：用户可挂多个角色；功能权限按节点去重。若多来源数据权限冲突，取**并集**。取消分配：从用户角色关系删除即可。
- **Q-PERM-5**：默认密码存在库里，走**字典配置**，不写死 `135`。
- **Q-TENANT-1**：用户、部门行上有租户对应字段；右上角公司名、菜单「归属租户类型」用这些字段。

## 本阶段范围

按 phase 逐步做。**当前只做：登录、用户、权限（菜单树）、角色的定义**。投放/素材/报表块不创建（Q-FE-2）。前端对接 OpenAPI 见 [0019](0019-后端OpenAPI对接.md)。

## 后果

实现与计划不得再把 102 行当「禁止当清单」。也不得把 102 个名称当成必须先做的前端页面。
