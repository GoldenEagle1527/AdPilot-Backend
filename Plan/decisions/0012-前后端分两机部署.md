# ADR 0012：前后端分两台机器部署

状态：accepted

## 背景

原先「前后端分离」只锁了接头是契约、不共享内部模型。新需求：前端和后端会部署在 **两台独立机器** 上，必须按跨机、跨源来设计。

## 决定

- 前端、后端是两套可独立构建、独立发布、独立运行的产物。
- 生产拓扑是 **两台机器**：一台只跑前端（静态站点或前端进程），一台只跑 FastAPI。彼此只通过 HTTP 调契约。
- 浏览器里的页面 **不得假定** 与 API 同源。后端基址由配置给出（环境变量 / 运行时配置），禁止写死某台机器的 IP 或域名进业务代码。
- 后端必须显式配置 CORS（允许的前端源）。开发机用代理可以，**不能**当生产模型。
- 生产上 **禁止** 用 FastAPI 托管前端页面作为正式部署方式，禁止服务端渲染业务页来「省一次跨机」。
- 仓库仍可以是一个（计划 + 两端代码同仓）；**部署产物是两份**，不是两个 Git 仓库的意思。

「模块化单体」只描述 **后端**：一个 FastAPI 进程、一业务一包。它不表示前后端打成一个进程。

## 后果

登录若用 Cookie，跨站成本高（`SameSite=None`、HTTPS、`Access-Control-Allow-Credentials`）。Q-AUTH-1 仍未锁，但两机部署使 **Authorization header 更顺**。主机名、TLS、是否前置反向代理见 Q-DEP-1。
