## 本轮范围

本阶段只定：**登录、用户、权限（菜单树）、角色、部门（授权机器所需）**。投放/素材/报表业务 CRUD 不在本表。  
框架健康检查不算业务契约：`GET /api/v1/health`、`GET /api/v1/ready`（见信封文档）。

登录路径在 `auth`（shared 槽），不在 `system-admin` 包内实现；契约仍登记在本目录，方便前端一份表看完。

## 全站约定（各契约不再重复解释）

| 项 | 约定 |
| --- | --- |
| 信封 | 成功 `{ ok: true, data, error: null }`；失败 `{ ok: false, data: null, error: { code, message } }` |
| HTTP | 业务失败仍用 4xx/5xx；`code` 大写蛇形 |
| 鉴权 | 除登录、health、ready、`/openapi.json`、`/docs` 外，必须带 `Authorization: Bearer <token>` |
| id | 系统生成的主键一律 **string**（十进制数字，避免 JS 精度） |
| 启停 | 字段名 `enabled`（boolean）。筛选项文案「使用中/已停用」由前端翻译，不另造字符串枚举 |
| 时间 | ISO-8601，UTC，带 `Z` |
| 分页 | `page` 从 1；`page_size` 默认 20、上限 100。`data` 为 `{ items, total, page, page_size }` |
| 树 | **不分页**。`data` 为 `{ items: [] }`，节点含 `children`（可空数组） |
| 替换写 | `PUT .../roles`、`PUT .../tags`、`PUT .../menus`、`PUT .../data-scope` 均为**整集替换**，不是增量补丁 |
| 租户 | 用户、部门上的 `tenant`（string）。创建时不传则取当前登录用户的 `tenant` |
| 禁止 | Cookie 登录；前端自算有效权限；权限码字段 |

## 共用错误码

各契约「错误」表只列本接口特有情况。下列默认适用于所有需登录接口：

| 情况 | HTTP | code |
| --- | --- | --- |
| 未带或 Token 无效 | 401 | UNAUTHORIZED |
| 已登录但无对应菜单/组件 | 403 | FORBIDDEN |
| 字段校验失败 | 422 | VALIDATION_ERROR |
| 资源不存在 | 404 | NOT_FOUND |
| 服务端未处理异常 | 500 | INTERNAL_ERROR |
