# 契约：sync-advertisers

业务id：oceanengine
文档版本：1
方法：POST
路径：/api/v1/oceanengine/sync/advertisers
作用：手动同步广告主名单、余额和公司名。

作者：
状态：draft
更新日期：2026-09-23

## 请求

无请求体。

| 字段 | 位置（path/query/body/header） | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Authorization | header | string | 是 | `Bearer <token>`。菜单节点 `64`。只有菜单 32 为 403 |
| oe_app_id | query | int | 否 | 只同步这一套应用。省略则同步全部有效应用 |

## 响应

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| advertiser_count | int | 本次写入或更新的未删除广告主行数 |

列表字段仍以广告主列表契约为准。本接口不返回巨量原文，也不新增余额字段名。`valid_balance` 只在列表里出现，类型保持 float。

`mock=true` 时不打开放平台，按库内种子把名单、余额、公司名重新对齐到表。

## 错误

| 情况 | HTTP 状态 | 说明 |
| --- | --- | --- |
| 未登录 | 401 | |
| 无菜单 64 | 403 | 只有菜单 32 的投手再调手动同步会 403 |
| `oe_app_id` 不存在 | 422 | |
| 同一应用已有未结束的广告主同步 | 409 | 整次不另开并行同步 |
| `mock=false` 且未配 secret | 503 | `巨量未配置` |

巨量失败不把上游 `message` 放进新的响应字段。名单已写入的行保持上次成功列；列表仍 200。

## 业务规则

- 本次同步没再出现的旧户标 `sync_status=missing`，不软删，已有投手保留。
- 余额或公司名失败不回滚已写入的名单。
- 菜单 63 的列表仍能看到 `missing`。只有菜单 32 的列表看不到。

## 被谁调用

授权组织页或联调时的手动同步。要求菜单 64，不是菜单 63。

## 内部

升级版工作台名单带 `query_type=TRAVERSE`。`total_number` 不超过 1 万时按页拉完。超过 1 万条不继续翻页，改为创建并查询 `ebp/advertiser/task`，完成后下载。任务未完成时不把未出现的户标成 `missing`，`task_id` 记在组织上，下次同步接着查。名单先落库。每次同步再补一批余额和公司名，单户失败不回滚名单。余额写入 `valid_balance`（float），公司名写入 `adv_company_name`。原文进 `raw_payload`，本接口与列表都不返回。
