## 已经做好

前缀 `/api/v1/standard-delivery`。模板、任务草稿、自动规则都是：列表、单条、新建、整表更新（`PUT`）、软删。确认提交不在这些接口里。

草稿一次只收一个已启用的标准抖音号（`douyin_account.delivery_mode=standard` 且 `enabled=true`），`native_setting.aweme_id` 用这一个号。同一草稿上的多个广告账户共用它。下拉不按投手过滤，不读 `douyin_pitcher`（那张表只给全域号）。

产品稿「按投手过滤抖音号」「根据分配的投手信息」「选择绑定了当前投手的抖音号」作废。以中台口径和同目录字段对照为准。

代码在 `backend/app/modules/standard_delivery/`。草稿模型自己写明：不存推广链、产品主图、卖点、行动号召、事件资产、地域 code、巨量商品 id、巨量视频 id。

## 草稿还没有的列

下面这些没有列，提交时不能从草稿表里读出来：

| 提交要用的 | 草稿里实际有的 |
| --- | --- |
| 专辑 URL（`playlet_series_url_list`） | 无 |
| 产品名称、主图、卖点、行动号召 | 无 |
| 巨量 `video_id` | 只有 `delivery_task_video.material_video_id`（素材库主键） |
| 巨量 `product_id` | 只有 `product_library_id`，对应商品库 `library_no`（`related_product.product_platform_id`） |
| `optimize_goal.asset_ids` | 只有优化目标枚举：免费 `AD_CONVERT_TYPE_ACTIVE`，付费 `AD_CONVERT_TYPE_PAY` |
| 地域 code（`audience.city`） | 无。版位在 `placement`：`aweme` / `aweme_feed` / `universal` |

`delivery_task_video.material_video_id`、`delivery_task_title.material_title_id` 不建外键。`material_videos` / `material_titles` 不在这条迁移链上，这台库上这两张表也可能还没有，保存时在应用层查。

草稿主表 `delivery_task_draft` 现有列：`template_id`、`charge_mode`、`pitcher_user_id`、`schedule_start`、`schedule_end`、`douyin_account_id`、`series_id`、`placement`、`project_budget`、`ad_budget`、`optimize_goal`、`product_library_id`。账户在 `delivery_task_account`（存广告主行，请求里用巨量广告主 id）。

模板表不存巨量创建项目的提交体。模板名称、主体、出价面板、每账户广告条数只留在本系统。

## 迁移

仓库不提交 alembic revision。`.gitignore` 有 `backend/alembic/versions/`。`git ls-files` 在这个目录里只有 `backend/alembic/versions/.gitkeep`。因此不要 `git add -f` 这一份。

本机文件（只在工作区，不在 git 里）：

- 文件：`backend/alembic/versions/20260929_01_standard_delivery.py`
- revision id：`20260929_01`
- down_revision：`20260928_01`

换机器开发时把这个文件一起拷走。`git pull` 不会带来它，也不会删掉工作区里已有的这份。

在这台机器上不要跑 `alembic revision --autogenerate`。模型里还有漫剧多出来的列，自动生成会把无关差异写进新 revision。表结构用上面这份手写迁移，在 `backend/` 里 `alembic upgrade head`。
