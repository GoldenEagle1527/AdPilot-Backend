# 漫剧标准投放 · 巨量接口对照

产品文档：《oc投放-智能投放-漫剧标准投放》。下面每张表的「产品文档原文」是文档里的原话，用来对传参。免费、付费走同一套接口，原文不同的地方单独标出。

公共 Header：`Access-Token`（本系统 OAuth 已有，[获取 Access Token](https://open.oceanengine.com/labels/7/docs/1696710505596940)）。JSON 用 `application/json`，上传图片/视频用 `multipart/form-data`。

页面标题里的「端原生」在巨量没有单独枚举。创建项目、创建单元必须同时带上下表，短剧专辑链接才会生效。白名单 key：`micro_app_aweme`。

| 巨量字段 | 传参 | 产品文档原文 |
| --- | --- | --- |
| landing_type | `MICRO_GAME` | 页面名「漫剧标准投放-(免费/付费)端原生」。巨量把端原生放在营销目的「小程序」下，枚举是 `MICRO_GAME` |
| ad_type | `ALL` | 同上。端原生要求营销类型为通投，枚举 `ALL`。这不是页面上的「通投智能选」 |
| marketing_goal | `VIDEO_AND_IMAGE` | 产品文档没写营销场景。端原生要求短视频+图文 |
| micro_promotion_type | `AWEME` | 模板第 11 条「抖音号」。端原生的投放载体是抖音号，枚举 `AWEME` |

## 1. 模板管理 → 创建项目

产品文档：「漫剧标准投放-(免费)端原生模板管理」「漫剧标准投放-(付费)端原生模板管理」。这些字段在提交任务时写入创建项目。模板名称、主体搜索、出价面板只存在本系统，不传巨量。

- 方法：`POST`
- 地址：`https://api.oceanengine.com/open_api/v3.0/project/create/`
- 文档：[创建项目](https://open.oceanengine.com/labels/7/docs/1740868093375503)
- 本系统已接：`POST /api/v1/oceanengine/projects`。`subject_id` 只落本地。`template` 里有则带上 `delivery_range`、`delivery_setting`、`optimize_goal`、`related_product`、`audience`、`micro_promotion_type`

| --- | --- | --- |
| advertiser_id | 投手选中的广告账户 id | 投放任务第 4 条：「账户：绑定了当前登录的投手账号绑定的账户，选择框为下拉框数据自动匹配三个账号可进行修改」。模板第 3 条的主体不传这个字段 |
| name | 任务提交时现拼 | 投放任务第 6 条：「项目名称：选择短剧后自动匹配名称，命名规则：（短剧前两个字）+NB+月日+当前时分」 |
| delivery_mode | 手动投放 `MANUAL`；自动投放 `PROCEDURAL` | 模板第 4 条：「投放模式“手动投放、自动投放两个字段切换选择（不可多选）」 |
| optimize_goal.external_action | 免费 `AD_CONVERT_TYPE_ACTIVE`；付费 `AD_CONVERT_TYPE_PAY` | 免费模板第 4 条：「优化目标：激活（下拉框只有这一个选项）」。付费模板第 4 条：「优化目标：付费（下拉框只有这一个选项）」 |

| audience.location_type | `CURRENT` / `HOME` / `TRAVEL` / `ALL` | 产品文档没写「正在该地区的用户」这句，定向图里若有位置类型就填这里。有 `city` 时巨量必填 |

## 3. 自动投放规则

产品文档：「漫剧标准投放-(免费)端原生自动投放」「漫剧标准投放-(付费)端原生自动投放」。规则保存和到点执行都在本系统。到点后仍然调用第 1、2 节，没有单独的「自动批量」巨量接口。

筛剧用的消耗、回收来自自定义报表：

- 方法：`GET`
- 地址：`https://api.oceanengine.com/open_api/v3.0/report/custom/get/`
- 文档：[自定义报表](https://open.oceanengine.com/labels/7/docs/1741387668314126)
- 本系统已接广告维度。指标 `stat_cost`、`attribution_micro_game_0d_roi`

| 巨量字段 | 传参 | 产品文档原文 |
| --- | --- | --- |
| 不传。执行时改用模板里的 `delivery_setting.bid_type=NO_BID` | 筛「最大转化」的剧 | 「任务逻辑：在什么时间范围内，最大转化竞价策略的剧目……自动生成对应的计划」。付费：「选择：只针对NO_BID出价：选中则只针对最大转化的类型剧目生效」 |
| metrics 含 `stat_cost` | 消耗，单位元（接口原始单位是十万分之一元，本系统已换成元） | 「短剧消耗范围n~n」。任务逻辑举例：「消耗在0-100这个范围」 |
| metrics 含 `attribution_micro_game_0d_roi` | 小程序当日变现 ROI | 「短剧回收率范围：n~n」。任务逻辑举例：「回收达到0.1-0.2」 |
| start_time / end_time | 报表查询的日期 | 「短剧上架时间：起始到结束时间表」是筛短剧库的上架时间，用 `manhua_series.publish_time`，不是报表时间 |

这些句子不传巨量：

| 产品文档原文 | 落到哪 |
| --- | --- |
| 「规则名称：命名规则：IAA端原生自动批量-年月日时分秒」 | 本系统规则名 |
| 「批量模版：选择（免费/付费）端原生模版管理中设置好的模版」 | 选中的模板提供第 1、2 节的全部传参 |
| 「剧场：番茄漫剧」 | 本系统筛短剧 |
| 「选择短剧（下拉框、可多选）：根据短剧资源库数据」 | `manhua_series` |
| 「每部剧使用新账户数：数字框（默认3，可修改）」 | 本系统分配账户个数，每个账户一次创建项目 |
| 「每部剧最大视频素材数：数字框（默认200，可修改）」 | 本系统从素材库截取视频条数，再按模板「每个广告使用视频数」拆成多条单元 |
| 「立即执行，创建完即可执行该任务」「预约执行……执行定时任务」 | 本系统调度 |

报表按广告返回，产品文档要的是短剧消耗和短剧回收。本系统要用广告名称或商品 id 归到 `manhua_series` 再求和。

## 4. 优化目标查询

模板下拉是写死的。提交前用这个接口确认该账户真有「激活」或「付费 / 付费ROI」，再写入 `optimize_goal`。

- 方法：`GET`
- 地址：`https://api.oceanengine.com/open_api/v3.0/event_manager/optimized_goal/get_v2/`
- 文档：[获取可用优化目标（体验版）](https://open.oceanengine.com/labels/7/docs/1740944984250381)
- 枚举：[转化类型](https://open.oceanengine.com/labels/7/docs/1696710760171535)
- 本系统未接

查询参数对产品文档：

| 巨量字段 | 传参 | 产品文档原文 |
| --- | --- | --- |
| advertiser_id | 任务选中的账户 | 投放任务第 4 条的账户 |
| landing_type | `MICRO_GAME` | 页面「端原生」 |
| ad_type | `ALL` | 端原生要求的通投 |
| delivery_mode | 与模板一致 | 模板第 4 条「手动投放、自动投放」 |
| micro_promotion_type | `AWEME` | 模板第 11 条「抖音号」 |

深度优化方式：

- 方法：`GET`
- 地址：`https://api.oceanengine.com/open_api/v3.0/event_manager/deep_bid_type/get/`
- 本系统未接
