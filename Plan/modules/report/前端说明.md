# 数据报表 · 前端对接

给做「数据报表」页面的前端。产品页面对应 [口径](../../product/数据报表/口径.md) 和同目录原型。字段级契约在 [contracts/最新表.md](contracts/最新表.md)。

基址：`/api/v1/reports`。本地 `http://127.0.0.1:8300`。请求头 `Authorization: Bearer <token>`。

成功时（导出除外）：

```json
{ "code": 200, "message": "成功", "data": {} }
```

失败时 `code` 等于 HTTP 状态，`message` 是一句中文。未登录 401，没有菜单 403，行不可见 404，参数不合法 422。

角色是负责人的账号（管理员）看全部行，不按投手、也不按组报表的部门范围过滤。其余账号只看自己是投手的行；组报表看数据权限里的部门。

列表的 `data` 都是：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "page_size": 20,
  "summary": {}
}
```

`page` 从 1 起，`page_size` 默认 20、最大 100。`summary` 是筛选和权限之后**全部行**的合计，不是当前页。日期 `YYYY-MM-DD`，北京时间，默认今天，起止都含当天。多选参数重复键名，例如 `panel=小额&panel=大额`。空数组不要传。排序 `sort_order` 为 `asc` 或 `desc`。

打开页面不打巨量。每小时先拉原始小时数，再刷成和列表同形的日表；列表读日表。近 8 天有数，更早的日期可能是空的。日表还没刷过时，列表是空的。趋势和时速仍按小时读原始表。

付费要菜单 9，免费要菜单 5。没有对应菜单是 403。

下钻：

- 剧目页点剧名或「项目/广告」：打开项目列表，带上这一行的 `series_id`。付费再带上这一行的 `panel`（空串也要带，用来对上没有面板的旧行）。
- 项目页点项目名：打开计划列表，带上 `series_id`。计划接口**没有** `project_id`，会出这部剧下自己的全部计划，前端若要只留当前项目，用返回的 `project_id` 自己滤。
- 计划名称、计划 ID 跳巨量或素材详情：本期没有中台接口，用返回的 `promotion_id` 自己拼巨量地址。
- 起量工具本期没有接口，按钮先不做。

## 漫剧报表

`charge_mode`：`IAP` 是 R1IAP 及其下钻，`IAA` 是 R1IAA 及其下钻。

### 剧目列表 `GET /manhua/dramas`

R1IAP、R1IAA。所选日期范围内一部剧一行。付费再按面板拆行，一行一个面板。多个投手姓名用 `、` 拼在 `pitchers`，消耗是这些人的合计。当前用户的名字在里面才返回这一行。

R1IAP 只传这些筛选，多传剧目、媒体以外的值、类型、渠道、优化师会 422：

| 参数 | 说明 |
| --- | --- |
| charge_mode | 必填，`IAP` |
| date_start、date_end | 默认今天 |
| bid_type | 多选：`最大转化`、`稳定成本` |
| panel | 多选，面板名 |
| drama_age | 多选：`新剧`、`老剧` |
| team | 多选，部门名称 |
| page、page_size、sort_by、sort_order | 默认按 `stat_cost` 倒序 |

R1IAA 在上面之外还可以传：`series_id`（多选剧目 id）、`series_name`（剧名模糊）、`media`（默认 `巨量`，别的值得到空列表）、`drama_type`（`真人剧`、`漫剧`）、`channel`（如 `番茄`）、`pitcher`（姓名，精确）。不要传 `panel`，传了 422。

`list` 一项：

| 字段 | 页面列 |
| --- | --- |
| series_id | 下钻用，不展示 |
| book_name | 剧目名称 |
| media | 投放媒体，恒为 `巨量` |
| drama_type | 剧目类型，`真人剧` / `漫剧`，对不上是空串 |
| channel | 剧目渠道，如 `番茄` |
| bid_type | 投放类型，多种用 `、` |
| panel | 面板。付费是本行那一个值，可能为空串。免费是该剧出现过的面板，用 `、` 连接 |
| drama_age | 新剧 / 老剧。上线日落在所选区间内是新剧 |
| teams | 团队，部门名，`、` 连接 |
| pitchers | 优化师，`、` 连接 |
| promotion_with_cost_count | 有消耗计划数 |
| 指标 | 见下方「漫剧指标」 |

`summary` 与指标字段相同，并带 `promotion_with_cost_count`。比率用合计重算，不要把各行比率加起来再除。

### 项目列表 `GET /manhua/projects`

IAP 项目、IAA 项目。一个巨量项目一行，只返回当前用户自己投的项目。

筛选比剧目页全：日期、`series_id`、`series_name`、`media`、`drama_type`、`channel`、`bid_type`、`drama_age`、`team`、`pitcher`。付费还可以传 `panel`，只用来过滤，响应里没有面板列。免费传 `panel` 是 422。从剧目点进来时带 `series_id`，付费再带 `panel`。

`list` 一项：

| 字段 | 页面列 |
| --- | --- |
| project_id | 项目 ID，巨量项目 id |
| project_name | 项目名称 |
| series_id、book_name | 剧目 |
| pitcher | 优化师，一个人 |
| team | 团队 |
| created_at | 项目创建时间，北京时间，可能为 null |
| first_cost_time | 项目开始有消耗时间，可能为 null |
| project_budget | 项目预算，可能为 null |
| roi_goal | ROI 系数，模板上的值，可能为 null |
| 指标 | 同剧目 |

不返回出价，也不返回起量工具。

### 计划列表 `GET /manhua/promotions`

IAP 计划、IAA 计划。一条广告一行，只返回自己的。筛选与项目列表相同。

在项目行字段之外：

| 字段 | 页面列 |
| --- | --- |
| promotion_id | 计划 ID |
| promotion_name | 计划名称 |
| created_at | 计划创建时间 |
| first_cost_time | 计划开始有消耗时间 |

`project_id`、`project_name`、预算、ROI 系数仍在。出价、起量不返回。

### 趋势 `GET /manhua/trend`

剧目、项目、计划行上的「查看」。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| charge_mode | 是 | `IAP` / `IAA` |
| grain | 是 | `drama` 剧目、`project` 项目、`promotion` 计划 |
| id | 是 | 剧目传 `series_id`，项目传 `project_id`，计划传 `promotion_id` |
| panel | 否 | 只给付费剧目。传这一行的 `panel`，空串表示没有面板的旧行。不传则把这部剧各面板加在一起 |
| date | 否 | 弹框里的单日，默认今天 |

`data`：

```json
{
  "date": "2026-10-13",
  "items": [{ "hour": 0, "stat_cost": 0, "stat_pay_amount": 0 }]
}
```

`stat_cost` 是消耗，`stat_pay_amount` 是回收。今天只到当前小时，过去的日子是 0 到 23，将来是空数组。到了但没有数的小时是 0。看不见这条数据是 404，文案 `报表行不存在或不可见`。

### 导出 `GET /manhua/export`

漫剧三页的「导出 Excel」。`level` 必填：`drama`、`project`、`promotion`。其余查询参数与对应列表相同。`page`、`page_size` 可以传，不生效。

成功不是 JSON，是 xlsx 文件。失败仍是信封。

### 漫剧指标

金额两位小数，ROI 四位小数，百分数两位小数。分母为 0 时比率是 0。

| 字段 | 页面列 |
| --- | --- |
| stat_cost | 消耗 |
| stat_pay_amount | 付费金额（趋势图里的回收） |
| pay_amount_roi | 回收 ROI，付费金额 / 消耗 |
| attribution_game_in_app_ltv_1day | 当日付费金额 |
| attribution_game_in_app_ltv_8days | 7 日付费金额 |
| attribution_micro_game_0d_ltv | 当日广告变现 LTV |
| attribution_micro_game_7d_ltv | 7 日广告变现 LTV |
| attribution_game_in_app_roi_1day | 当日付费 ROI |
| attribution_game_in_app_roi_8days | 7 日付费 ROI |
| attribution_micro_game_0d_roi | 当日广告变现 ROI |
| attribution_micro_game_7d_roi | 7 日广告变现 ROI |
| show_cnt | 展示数 |
| cpm_platform | 平均千次展现成本 |
| click_cnt | 点击数 |
| cpc_platform | 点击成本 |
| active | 激活数 |
| active_cost | 激活成本 |
| convert_cnt | 转化数 |
| conversion_cost | 转化成本 |
| ctr | 点击率，已乘 100 |
| active_rate | 激活率，已乘 100 |
| conversion_rate | 转化率，已乘 100 |

`sort_by` 用这些字段名，剧目页还可以用 `promotion_with_cost_count`。

## 漫剧全域报表

没有导出，没有字段选择器。列头排序用 `sort_by`、`sort_order`，默认 `all_stat_cost_trend` 倒序。

原型上的「平台」下拉、「投手」下拉、「分组筛选」本期没有对应查询参数。`series_name` 只在两个短剧 tab 上过滤剧名；投手报表和组报表传了也不生效。

### 短剧收益 `GET /uni/dramas`

菜单 13。一部剧一天一行。没有投手列。当天多人投同一部剧时，数是他们的合计；当前用户是其中之一才看得到。

| 参数 | 说明 |
| --- | --- |
| date_start、date_end | 默认今天 |
| series_name | 剧名，模糊 |
| page、page_size、sort_by、sort_order | |

`list` 一项：`series_id`、`book_name`（短剧名称）、`platform_name`（平台，如 `番茄`，对不上是空串）、`stat_time_day`（日期），加上「全域指标」。时速弹框用 `series_id` 和这一行的 `stat_time_day`。

### 投手短剧收益 `GET /uni/pitcher-dramas`

菜单 13。一个投手、一部剧、一天一行。只返回当前用户自己的行，数不含同剧其他投手。

字段在短剧收益之上多 `pitcher_user_id`、`pitcher_name`。查询参数与短剧收益相同。

### 投手报表 `GET /uni/pitchers`

菜单 14。自己一天一行。

查询只有日期、分页、排序。`list` 一项：`pitcher_user_id`、`pitcher_name`、`stat_time_day`、全域指标、`new_drama_count`（新建新剧数，恒为 0）。时速用 `pitcher_user_id`。

### 组报表 `GET /uni/groups`

菜单 15。一个部门一天一行。看数据权限里的部门；权限为空则只看自己所在部门。每个投手的数只进自己的部门。

`list` 一项：`department_id`、`department_name`（小组）、`stat_time_day`、全域指标、`new_drama_count`（恒为 0）。时速用 `department_id`。

### 时速 `GET /uni/speed`

四个全域页的「消耗时速」。

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| scope | 是 | 两个短剧 tab 用 `drama`，投手报表用 `pitcher`，组报表用 `group` |
| id | 是 | `drama` 传 `series_id`，`pitcher` 传 `pitcher_user_id`，`group` 传 `department_id` |
| date | 否 | 这一行的日期，默认今天 |

`data`：

```json
{
  "date": "2026-10-13",
  "previous_date": "2026-10-12",
  "cost": {
    "current": [{ "hour": 0, "value": 0 }],
    "previous": [{ "hour": 0, "value": 0 }],
    "growth_rate": [{ "hour": 0, "rate": 0 }]
  },
  "recovery": { "current": [], "previous": [], "growth_rate": [] }
}
```

消耗 tab 用 `cost`：`current` 是所选日，`previous` 是前一天，`rate` 是分时增长率 `(当天该小时 - 前一天同一小时) / 前一天同一小时`，前一天为 0 时增长率是 0。回收 tab 用 `recovery`，三个数组目前都是空的，图可以空着。小时规则与漫剧趋势相同。看不见是 404。

### 全域指标

金额两位小数，ROI 四位小数。

| 字段 | 页面列 |
| --- | --- |
| all_stat_cost_trend | 全域消耗 |
| all_roi_24h_trend | 24 小时 ROI |
| all_stat_total_cost_trend | 全域成本 |
| all_gmv_trend | 全域 GMV |
| all_billing_gmv_0day_trend | 当日全域 GMV |
| all_billing_gmv_24h_trend | 24 小时全域 GMV |
| all_billing_gmv_3days_trend | 三日全域 GMV（三日 ROI 的分子，页面可不单列） |
| all_roi_trend | 全域 ROI |
| all_roi_0day_trend | 当日全域 ROI |
| all_roi_3days_trend | 三日全域 ROI |
| all_income_trend | 全域收入 |
| all_income_0day_trend | 当日全域收入 |
| all_pay_amount_income_trend | 付费收入（短剧两个 tab 有，投手/组报表的表头可以不展示） |
| all_micro_game_income_trend | 变现收入（同上） |
| new_project_count | 当天新建项目数 |
| new_project_with_cost_count | 当天新建项目数（有消耗），恒为 0 |
| spending_project_count | 在消耗项目数，恒为 0 |

## 利润报表

四个页面共用五个页签，查询参数 `mode`：

| 页签 | mode |
| --- | --- |
| 合计统计（全域+标准） | `all` |
| 合计统计（标准） | `standard` |
| IAA 统计 | `iaa` |
| IAP 统计 | `iap` |
| 全域统计 | `uni` |

金额两位小数。回收率、盈亏由接口算好。盈亏负数页面用绿色，正数用红色。赔付消耗这列不要做。维利润统计不要做。每日利润展开后也是消耗、回收、回收率、盈亏，没有修正消耗和充值。

`platform`：`tomato` 显示番茄，`ouxi` 显示鸥溪。`drama_type`：`漫剧` 或 `真人剧`。

| 页面 | 菜单 | 列表 | 点开 |
| --- | --- | --- | --- |
| 利润统计概览 | 23 | `GET /profit/overview` | `GET /profit/overview/departments`，起止日期都传被点的那一天 |
| 每日利润统计 | 24 | `GET /profit/daily` | `GET /profit/daily/platforms` |
| 投手利润统计 | 28 | `GET /profit/pitchers` | 无 |
| 组利润统计 | 29 | `GET /profit/groups` | `GET /profit/groups/pitchers?department_id=` |

概览多一个 `department_id`。每日利润多一个 `pitcher_user_id`；投手登录时这个参数无效，接口只回他自己。负责人和运营管理员可以筛投手。

ROI 配置在概览页，四张表共用：

| 动作 | 接口 |
| --- | --- |
| 列表 | `GET /profit/roi` |
| 新增 | `POST /profit/roi`，body：`date_start`、`date_end`、`roi_rate` |
| 修改 | `PUT /profit/roi/{id}`，body 同上 |
| 删除 | `DELETE /profit/roi/{id}` |

日期重叠时，利润用创建时间最新的那条。没配到的日期按 1.00。

行上的四个数字：`stat_cost` 消耗，`recovery` 回收，`recovery_rate` 回收率，`profit` 盈亏。顶部汇总用 `summary` 的同名字段，回收率已经是总回收除总消耗。

## 素材报表

自定义列和封面悬停播放都在前端做。接口给全字段，视频地址是 `file_url`。

| 页面 | 菜单 | 列表 |
| --- | --- | --- |
| 素材消耗 | 17 | `GET /materials/spend` |
| 素材消耗 · 数据详情 | 17 | `GET /materials/spend/detail` |
| 剪辑师消耗 | 18 | `GET /materials/editors` |
| 素材报表 · 短剧统计 | 19 | `GET /materials/dramas` |
| 素材报表 · 短剧素材手 | 19 | `GET /materials/drama-editors` |
| 素材报表 · 素材统计 | 19 | `GET /materials/videos` |
| 素材报表 · 未上 NB 新剧 | 19，还要组件 20 | `GET /materials/nb-dramas` |
| 剪辑师统计 | 21 | `GET /materials/editor-stats` |

素材消耗的筛选是 `pitcher_user_id`、`uploader_id`。点数据详情时，行上有 `video_id` 就传它，没有就传 `ocean_material_id`，两个不要一起传。`delivery` 用 `all`、`standard`、`uni`。详情里千次展示费用是 `cpm`，已经乘过 1000。点击率 `ctr`、转化率 `conversion_rate` 是百分数。

剪辑师消耗：`cost_ex_nobid` 是总消耗减标准 nobid，`uni_gmv` 是全域回收，`group_avg_roi` 是登录人所在部门、当前查询区间的平均 ROI。汇总行这个字段是 null，格子留空。

短剧三个 tab 的新老剧用重复参数 `drama_age=新剧`。新剧是预估可投日落在所选日期里。从短剧统计点剧名，打开素材统计并带上 `series_name`。从短剧素材手点剧名，再带上 `uploader_id`。

未上 NB 的日期是预估可投日，不是消耗日。`material_count` 可以是 0。

剪辑师统计点数据详情，前端自己跳到短剧素材手，把 `uploader_id` 带上。剪辑师账号和打了「素材手」标签的账号，在短剧素材手、素材统计、剪辑师统计只能看到自己。字段级说明在 [contracts/最新表.md](contracts/最新表.md)。
