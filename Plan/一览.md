# 协作与权限一览

给人过一眼的总表。细则仍以 `architecture/`、`modules/system-admin/` 为准。  
搭框架的执行步骤在 `backend/搭框架/` 与 `frontend/搭框架/`。菜单/角色清单按 xlsx（[权限清单-参考.md](modules/system-admin/权限清单-参考.md)）；不要按 102 行预建投放页。

---

## 1. 模块怎么分

先按**业务**切，不按「前端组 / 后端组」切第一刀。一个 FastAPI 进程，一个业务一个 Python 包。

| 模块 | 现在有没有 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| `shared` / `core` / 壳 | 约定已有；框架阶段要落地 | 启动、配置、日志、错误信封、分页、CORS、DB/Redis 连接、登录态怎么带、布局空槽 | 用户/角色/菜单/业务数据 |
| `system-admin` | 计划已有 | 部门、用户、角色、授权机器（树 + 绑定 + 可见部门） | 投放/素材/报表的领域数据 |
| 以后的业务块（例：投放） | 无，等业务来再复制 `_template` | 自己的领域表和页面 | 自建一套角色管理 |

| 规则 | 说明 |
| --- | --- |
| 一业务一包 | 目录：`app/modules/<business>/` 与 `frontend/src/modules/<business-id>/` |
| 部门/用户/角色不拆成三个模块 | 互相引用；并行靠包内文件，不靠再切业务 |
| 跨模块 | 只调对方**公开契约 / 公开窄口**，禁止 import 内部 ORM |
| 新模块 | 只许复制 `Plan/modules/_template/` |

## 2. 前后端怎么分

前后端 **完全分离**，部署在 **两台独立机器** 上（ADR 0012）。接头是 **HTTP 契约**，不是共享内部模型，也不是同一个进程。后端栈已定（ADR 0014）。前端 **React**（ADR 0015）。配置走 `deployment/*.yaml`。

| 端 | 落点 | 一个人可以只领 | 部署 |
| --- | --- | --- | --- |
| 后端 | `app/modules/<business>/api/<资源>.py` | 一个 router 文件 = 一组相关接口 | 后端机：一个 FastAPI 进程 |
| 前端 | `frontend/src/modules/<business-id>/pages/<页>/` | 一个页面（或页上一个能力） | 前端机：静态资源 / 前端进程 |
| 规格 | 后端 OpenAPI | 后端改接口；发对接文本 | 前端自己拉 |

浏览器只打开前端机。页面用 **可配置的 API 基址** 调后端机。禁止写死后端 IP、禁止假定同源、禁止生产用 FastAPI 托管页面。后端 `core` 配 CORS。细则：[architecture/前后端分机.md](architecture/前后端分机.md)。

当前先 **两人搭框架**（可并行）：

| 人 | 执行目录 | 做到哪 |
| --- | --- | --- |
| 后端框架 | [backend/搭框架/](backend/搭框架/说明.md) | 进程、core、yaml、共用 PG18/Redis、信封、健康检查、`0.0.0.0`+防火墙；空挂 `system_admin` |
| 前端框架 | [frontend/搭框架/](frontend/搭框架/说明.md) | Vite+React、目录、可配基址、Header Token、拆信封、空壳；不写投放 CRUD |

框架完成之后，业务仍按下面认领面拆接口/页面。合规见 [meta/公司研发规范.md](meta/公司研发规范.md)。

同一业务里：后端实现接口并保持 OpenAPI 正确；前端只按 OpenAPI 发请求、画界面。前端不抄字段表、不写自有业务逻辑。规则：[architecture/两仓通信.md](architecture/两仓通信.md)。

`system-admin` 对齐关系：

| 页面（前端认领） | 后端认领面（可再拆到单文件） |
| --- | --- |
| 部门管理 | `departments` / `department_tags` / `department_roles` |
| 角色管理（含勾菜单） | `roles` / `role_menus` / `menu_nodes` |
| 用户管理（含用户角色、数据权限、重置密码） | `users` / `user_roles` / `user_data_scope` / `password_reset` |
| 权限角色查询 | `menu_nodes`（只读） |
| 无独立页：壳和其它业务 | `session_queries` + `require_menu`（公开能力） |

## 3. 人怎么领接口（框架之后）

当前阶段是两人各领一端框架。框架完成后再回到认领三层：**业务块 → 前端或后端 → 一个接口文件或一个页面**。默认领第 3 层。

| 场景 | 怎么做 |
| --- | --- |
| 一人一个接口 | 在后端仓实现 router，OpenAPI 能看到 |
| 一人多个接口 | 领同一业务里多个 router；一次 PR 仍按接口分开更好 |
| 一人一个页面 | 等后端发出该接口（OpenAPI 可拉）以及对接文本 |
| 两人同时：一人接口一人页面 | 后端先把接口挂上；前端按对接文本去拉规格 |
| 不要 | 前端自己发明字段或业务规则 |

没有可拉的 OpenAPI、也没对接文本 = 前端当接口不存在。

页面不必再抄参数表。分支在**自己的应用仓**：`feat/<business>/<short>`。

## 4. 团队怎么通信

需求在**线下或群**里说。`Plan/` 只是现在把计划写下来，不是第三个仓。

| 渠道 | 用来干什么 |
| --- | --- |
| 群 / 线下 | 需求；对接文本；origin / API 基址 |
| 后端 OpenAPI | 字段、路径、类型（前端自己拉） |
| 各应用仓 Git | 本端代码；暂不加 origin |

## 5. 这套权限系统长什么样

要搭的是跟截图**同类的机制**。树上有哪些节点、有哪些角色，本阶段按 xlsx 清单。投放等**页面**仍不预建。

### 5.1 机制总表

| 概念 | 是什么 | 不是什么 |
| --- | --- | --- |
| 用户 | 账号；一人一个所属部门 | 功能权限不写在用户身上 |
| 角色 | 功能权限的容器（名称、备注、启停） | 不是「负责人/成员」（那是用户字段） |
| 用户角色 | 给人单独挂的角色 | 不是列表上只读的「部门角色」 |
| 部门角色 | 给部门挂的角色，用户只读继承 | 不是数据权限 |
| 菜单节点 | 目录 / 菜单 / 组件，同一棵树 | 不是权限码表 |
| 数据权限 | 用户勾选的可见部门集合 | 不是所属部门，也不是「全部/仅本人」档位 |

### 5.2 两根轴

| 轴 | 对象 | 绑在谁 | 干什么 |
| --- | --- | --- | --- |
| 功能权限 | 树节点（目录只分组；菜单=页面；组件=页内能力） | 角色 → 再经用户角色/部门角色到人 | 能不能进这个页面、用这个按钮 |
| 数据权限 | 部门 | 直接绑用户 | 业务数据按哪些部门过滤 |

```
用户 ──用户角色──► 角色 ──勾选──► 菜单/组件
  │                  ▲
  ├──所属部门──► 部门角色（只读继承）
  └──数据权限──► 可见部门集合（可空，可与所属部门不同）
```

### 5.3 现在定 / 现在不定

| 现在定 | 现在不做 |
| --- | --- |
| 用户、角色、树、两套角色绑定、可见部门 | 投放/素材/报表业务块与页面 |
| 清单按 5.4.0 xlsx（节点名可进树当数据） | 按 102 个名称预建假路由 |
| 其它业务不自建权限台，只调公开检查 | 另造权限码 |
| 壳问「当前用户有效节点 / 可见部门」 | 复刻截图视觉 |

本阶段**定义**登录/用户/权限/角色。节点进树是数据，不是前端页面全集。

### 5.4 其它业务怎么用

| 要做 | 不要做 |
| --- | --- |
| 有页面时，在 `system-admin` 树上登记节点 | 抄参考导出的 102 个名称当我们必须做的页 |
| 接口里调 `require_menu`；按部门过滤时用可见部门 id | 自己再做角色表 / 权限码 |
