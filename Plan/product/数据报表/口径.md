## 行

- R1IAP、R1IAA：所选日期区间内一部剧一行。日期是筛选，不是列。一部剧有多个投手：投手放一个格子，姓名用 `、` 连接；指标是这几个投手数据之和。
- R1IAP 还按面板拆行：一行恰好一个面板值。
- 短剧收益（tab1）：一部剧一天一行。日期既是筛选，也是列（`stat_time_day`）。没有投手列。当天多个投手投这部剧时，指标是这几个投手数据之和；当前用户是其中之一才看得到该行。
- 投手短剧收益（tab2）：一个投手、一部剧、一天一行。日期是列。投手列只有一个人，不拼接。指标只算该投手自己的项目，不加同剧其他投手。当前用户只看得到自己的行。
- R1IAA：面板是列，没有面板筛选。
- IAA项目、IAA计划：没有面板列，也没有面板筛选。
- IAP项目、IAP计划：面板只是筛选，不单独成列。
- 投手报表：一个投手一天一行。日期既是筛选（区间，默认当天），也是列（`stat_time_day`）。
- 组报表：一个部门一天一行。日期同投手报表，既是筛选也是列。
- 组报表汇总：每个投手自己的项目只计入该投手所在部门。不把整部剧的合计复制到每个部门；一部剧的投手分属两个部门时，各投手的消耗只进各自部门。

## 权限

- 除组报表外所有页面：当前用户的姓名在该行投手里，才看得到该行。角色为负责人（管理员）不按投手过滤，看全部行。
- 组报表：可见部门 = 当前用户的数据范围；数据范围为空时，只看自己所在部门。负责人看全部部门。
- 巨量项目匹配不到中台任务：仍留在数据集里，剧名一栏用巨量项目名，投手为空。它不出现在按个人过滤的页面上，也不计入任何组的合计。

## 剧目类型

只有两种：`真人剧`、`漫剧`。来自剧场应用风格：`live_action` → 真人剧，`manhua` → 漫剧。

不加 3D漫剧、AI仿真人剧、2D动态漫等原文列出的其它类型。

## 指标

| 项 | 口径 |
| --- | --- |
| 项目 id | `cdp_project_id` |
| 计划/广告 id | `cdp_promotion_id`。字段表里「计划就是项目」的备注作废 |
| 漫剧趋势弹框 | 所选那一天，按小时的 `stat_cost`、`stat_pay_amount`。还没到的小时不返回 |
| 汇总 ROI | `sum(回收) / sum(消耗)`，不是各行比率的平均 |
| 全域时速弹框 | 两个 tab：消耗、回收。按小时对比前一天与所选日，带分时增长率。消耗用 `all_stat_cost_trend`。`UNI_PROJECT_DATA` 没有 `stat_pay_amount`，回收 tab 目前为空 |
| 开始有消耗时间 | 第一个 `stat_cost > 0` 的快照时间。不用 `attribution_convert_cnt` |
| 有消耗计划数 | 区间内该剧（R1IAP 再加该面板）下 `stat_cost > 0` 的计划去重数 |
| 当天新建项目数 | 当天在中台提交成功的项目数 |
| 当天新建且有消耗、在消耗项目数、在消耗广告主数、新建新剧数 | 固定为 0 |

## 筛选

以原型图为准，不按原文更长的文字清单。

| 页面 | 筛选项 |
| --- | --- |
| R1IAP | 日期、投放类型、面板、新/老剧、团队 |
| R1IAA | 日期、剧目、媒体（默认巨量）、剧目类型、渠道、投放类型、新/老剧、团队、优化师。无面板 |
| IAP项目、IAP计划 | 完整筛选：日期、剧目、媒体、剧目类型、渠道、投放类型、面板、新/老剧、团队、优化师 |
| IAA项目、IAA计划 | 同上，但没有面板 |

- 媒体、渠道的选项页面上都有。本期数据只有巨量 + 番茄。鸥溪作为剧场平台存在，有关联数据时才出现。
- 新剧：`publish_time` 的日期落在所选区间内。更早的是老剧。
- 团队：即用户所在部门（部门表）。筛选值是部门名称。没有单独的团队实体。
- 投手报表、组报表：日期筛选是区间，默认当天。

## 刷新与页面功能

- 每小时先把巨量原始小时数写入 `oe_delivery_report`、`oe_uni_project_report`，再刷成与列表同形的日表（`report_manhua_*_day`、`report_uni_*_day`）。列表读日表。剧目、项目、计划的日期是区间、对外合成一行，所以只把区间内的日行相加，不再扫小时明细，也不再在请求里关联中台。全域列表本身一天一行，按日期直接取出。
- 趋势和时速弹框要的是小时，仍读小时原始表。
- 打开页面不调巨量。
- 漫剧报表页：自动刷新开关、手动刷新、字段选择器、导出 Excel、默认按消耗倒序。字段顺序归前端；接口返回整行。
- 全域报表页：列排序和顶部汇总。没有字段选择器，没有导出 Excel。

## 落库（已落地）

- 标准投放：确认提交成功后，每个建出的巨量项目写一行 `delivery_task_project`（`task_id`、`advertiser_account_id`、`bid_panel`、`ocean_project_id`、`sort_order`）；每个广告写一行 `delivery_task_promotion`（`task_project_id`、`ocean_promotion_id`、`sort_order`）。
- `delivery_task_account.ocean_project_id` 只在该账户恰好建出一个项目时填写。IAP 按面板拆成多个项目时，该列保持为空，按面板的项目看 `delivery_task_project`。
- IAP：一个（账户 × 出价面板）对应一个巨量项目，`bid_panel` 只存这一个面板名。旧的多面板项目保持一行，面板留空。
- 全域（`uni_native_task_account`）：已有 `ocean_project_id`，已加 `ocean_promotion_id`。仍是一个账户一个项目，不按面板拆。项目命名规则不变（剧名前两字 + NB + 时间）。
