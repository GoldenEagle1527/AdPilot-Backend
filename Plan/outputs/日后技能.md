# 日后 Cursor skills（步骤要点）

状态：accepted  
现在不要创建这些 skill 文件。实现期写成可调用的步骤，细节以 Plan 模板为准。

## S1 — 新建业务块

1. 复制 `Plan/modules/_template/` → `Plan/modules/<id>/`。
2. 改 `说明.md`：职责、以及「不自建权限台、走 system-admin 菜单树 + 可见部门」。
3. 在 `modules/说明.md` 登记。若有新页面，**届时**在 `system-admin` 菜单树登记节点，不要把参考导出的节点名抄进去。
4. 实现期：加 FastAPI 包与前端目录，只挂载；鉴权只调 `system_admin` 公开窄口。前端、后端分开部署（ADR 0012）。

## S2 — 新建接口

1. 确认业务块已存在。
2. 领接口的人复制契约模板为 `contracts/<endpoint-id>.md`，填文档版本 `1`、方法、路径、一句话、请求字段、响应字段、错误；变更历史写「初稿」。
3. 在 `contracts/最新表.md` 加一行；在该业务 `后端.md` 加一行指向该契约。
4. 若已有页面在用：同步 `pages/*.md` 调用表，并填契约「被谁调用」。
5. 实现期：在该业务包内新增 router 文件，不要放到别的包或 `core`。

## S3 — 新建页面

1. 确认所依赖的接口契约已存在且字段表完整。
2. 复制 `pages/页面卡片.模板.md` 为 `pages/<page>.md`，填调用表（动作 → 契约 → 字段名，不抄类型）。
3. 在 `前端.md` / `pages/说明.md` 登记。
4. 在每份被调用契约的「被谁调用」补一行。
5. 实现期：页面放 `frontend/src/modules/<id>/pages/`。请求走配置的 API 基址打到后端机，不要写死后端地址。代码、卡片、契约三者要一致。

## S4 — 变更接口

规则全文：[architecture/契约版本.md](../architecture/契约版本.md)。

1. 判断是否破坏性（删字段、改语义、改路径）。若是：先把当前契约全文复制为 `contracts/_history/<endpoint>-v<旧文档版本>.md`。
2. 改正文最新表；文档版本 +1；路径仅破坏性时升 `/api/vN`。
3. 变更历史**最上行**追加：日期、新版本、是否破坏、改了什么、作者。
4. 更新 `contracts/最新表.md` 对应行。
5. 字段名变了则同步仍在使用的 `pages/*.md`。停在旧版的页面链 `_history/`。
6. 实现代码与最新表不一致 = 未完成。只改说明、不改语义：可不升版本，仍记一行「文档」。

## S5 — 搭后端框架

按 [`../backend/搭框架/步骤.md`](../backend/搭框架/步骤.md) 从头做到 [`验收.md`](../backend/搭框架/验收.md)。OpenAPI 可访问。改接口发对接文本。

## S6 — 搭前端框架

按 [`../frontend/搭框架/步骤.md`](../frontend/搭框架/步骤.md)。框架已定 React（ADR 0015）。不要实现投放/素材/报表页，不要自有业务逻辑，规格拉 OpenAPI。
