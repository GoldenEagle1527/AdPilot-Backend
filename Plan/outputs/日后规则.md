# 日后 Cursor rules（禁令要点）

状态：accepted  
现在不要创建这些文件。实现期每条做成短 rule，`alwaysApply` 或按 glob 视落地时再定。

正文必须能链回 [`../meta/已定.md`](../meta/已定.md)、[`../architecture/模块化.md`](../architecture/模块化.md)、[`../architecture/共享白名单.md`](../architecture/共享白名单.md)、[`../backend/接口变更对接.md`](../backend/接口变更对接.md)、[`../architecture/前后端分机.md`](../architecture/前后端分机.md)、[`../meta/公司研发规范.md`](../meta/公司研发规范.md)。

## R1 — 禁止跨业务引用内部实现

业务包不得 import 另一包的内部模型、私有 schema、内部函数。  
例外（仍须有契约）：其它包可以 import `system_admin` 的**公开窄口**（有效菜单、可见部门、`require_menu`），见 `architecture/融合.md`。

## R2 — 前端只打后端；规格看 OpenAPI

前端不得实现自有业务逻辑。业务请求必须打后端。字段以 OpenAPI 为准，禁止在前端仓另抄一份字段表。health / ready 属框架，按 [`信封与分页.md`](../architecture/信封与分页.md)。

## R3 — 业务不得进入 shared

`core` / 前端 `shared` / `shells` 只准 [`../architecture/共享白名单.md`](../architecture/共享白名单.md) 白名单。业务名词、业务模型、业务页面、业务菜单内容不准进入。

## R4 — 机制跟截图同类，禁止另造真源；清单用 xlsx，不要预建 102 页

授权机制以 [`../modules/system-admin/权限模型.md`](../modules/system-admin/权限模型.md) 为准。禁止平行权限码表、第二套权限后台。本阶段菜单/角色清单按 `5.4.0.权限管理-权限角色查询表.xlsx`（见 [`权限清单-参考.md`](../modules/system-admin/权限清单-参考.md)，ADR 0016）。禁止为清单里每个节点预建投放/报表页面（Q-FE-2）。登录态仍只属于 shared。

## R5 — 新业务必须走模板

新增业务只能复制 `Plan/modules/_template/`（代码侧对应一业务一包）。禁止另起一套目录结构。

## R6 — 改接口必须更新 OpenAPI 并发对接文本

对外 HTTP 有变化时：OpenAPI 必须已是新的，并按 [`../backend/接口变更对接.md`](../backend/接口变更对接.md) 发群一段对接短文。禁止只改代码不发通知。禁止在对接文本里贴整份 schema。

## R7 — 前后端两机两仓；禁止同源假设与后端托管前端

前端、后端两套产物、两台机器、两个应用仓（ADR 0012/0018）。禁止生产用 FastAPI 托管业务页面；禁止在页面或业务模块写死后端 IP/域名；禁止把同源相对路径 `/api/...` 当唯一配置。CORS 与 API 基址只放 shared/`core`。细则：[`../architecture/前后端分机.md`](../architecture/前后端分机.md)、[`../architecture/两仓通信.md`](../architecture/两仓通信.md)。

## R8 — 公司研发规范：版本、许可证、面板、素材

遵守 [`../meta/公司研发规范.md`](../meta/公司研发规范.md)。禁止宝塔等非标面板；Redis 只准 7.2.x；PostgreSQL 只准 18.x；禁止未审批引入 GPL/AGPL/LGPL/EPL（含 psycopg）；素材须可商用。

## R9 — 后端栈不得改口

后端按 ADR 0014：FastAPI、SQLAlchemy 2 asyncio、asyncpg、Alembic。禁止另选 ORM/驱动「图省事」。表模型不得进入 `core`。
